# V31 Release Checkpoint — 2026-08-30

This checkpoint records the public/private beta baseline being promoted after the V31 intelligence and presentation work merged to `main`.

## Product baseline

- Role-first Agentic Sourcing entry points are first-class public/private product surfaces.
- Canonical agentic plans use distinct hypotheses, visible blind spots, truthful source modes, search memory, and recruiter-controlled learning.
- Domain Packs compose by confidence across technical, healthcare, research, federal/GovCon, finance, aviation, and general sourcing contexts.
- Healthcare provider scenarios can execute the privacy-minimized CMS NPI Registry adapter; healthcare-tech roles do not inherit that adapter automatically.
- Federal/GovCon context does not claim an executable public people source unless another applicable domain contributes one.
- USAspending organization-level signals can influence recruiter-selected target organizations but never create candidate claims.
- O*NET 31.0 occupational intelligence uses the official downloadable dataset transport. Related occupations, reported titles, and software examples are expansion hints only and do not rewrite recruiter-approved must-haves.

## Presentation baseline

- One persistent Light / Dark / System preference spans public and authenticated SourcingOS surfaces.
- The public light palette has increased contrast to avoid white-on-white / low-contrast states.
- The authenticated recruiter workspace supports the same theme preference while preserving the dark cockpit option.

## Trust boundaries

- Public evidence is not verified candidate fact.
- External content is treated as untrusted data, never instructions.
- Restricted/manual sources are labeled guided rather than falsely claimed as executed.
- No automatic outreach, rejection, consequential hiring action, or silent identity merge is introduced by this release.
- Organization-level market signals influence where recruiters may choose to search; they do not establish facts about individual candidates.

## Privacy boundary

- No private employer, project, personal, or client-specific data belongs in public demos, fixtures, docs, or release notes.
- O*NET transport does not send full job descriptions, candidate records, or recruiter notes to the dataset source.

## Next intelligence sequence

The next tranche should build on this baseline rather than create another parallel search engine:

1. Requirement-level candidate evidence matching with Supported / Contradicted / Unknown states.
2. Advocate / Skeptic / Unresolved analysis without collapsing disagreement into a score.
3. Search-quality evaluation: Precision@K, Recall@K, nDCG, MRR, lane contribution, novelty, calibration lift, and recruiter override metrics.
4. Probabilistic multi-source identity-resolution evaluation, routing ambiguous matches to recruiter review.
5. Additional authoritative registry adapters where they improve evidence/discovery quality.
6. Broader organization-signal coverage behind a normalized signal adapter.
7. Local/private document extraction experiments for PDF/DOCX parsing.
8. One direct ATS write-back adapter when a real pilot workflow requires it.

This file is descriptive only. It changes no auth, database, RLS, source-execution permissions, candidate data, or hiring-action behavior.
